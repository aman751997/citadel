## Why a canon exists

Machine-coding rounds draw from a surprisingly small pool. Interviewers reskin them — "parking lot" becomes "warehouse slotting", "Splitwise" becomes "team lunch settle-up" — but the *skeleton* repeats: a resource allocator, a money splitter, a state machine, a matcher. Learn the twelve skeletons and you've seen the reskins too. First, one worked end-to-end.

## Parking lot, through the protocol

### Phase 1 — requirements and the cut

Actors: driver, operator. Operations that must demo: **park, unpark, fee**. Varies: vehicle types (bike/car/truck), spot types, pricing. Invariants: one vehicle per spot; a ticket unparks exactly once; fee covers the full stay. Cut list: no payments integration, no reservations, single entry gate, in-memory. Concurrency: design for it, coarse-to-fine if asked (the [concurrency lesson's](/citadel/lld/lessons/concurrency-for-lld/) parking example is stage two of this exact problem).

Calls made out loud: `Ticket` is an **entity** (identity survives change; status flips OPEN→CLOSED). `Money` is a **value**. Spot occupancy is guarded *inside* `Spot` (`tryAssign`, not `isFree`+`assign` — that gap is the race from the concurrency lesson). Vehicle types are an **enum**, not a class tree — the electric-SUV follow-up cuts across any tree you'd guess (object-modeling lesson's exact warning).

### Phase 3 — the seams

Two interfaces carry all the flex: `SpotAllocationStrategy` (nearest / first-free / distribute-across-floors) and `FeeStrategy` (hourly / slab / weekend surge). Both Strategy + registry from the [behavioral lesson](/citadel/lld/lessons/behavioral-patterns/). `TicketRepo` hides the map.

### Phase 4 — the core flow

```java
public Ticket park(Vehicle v) {
    Spot spot = allocation.allocate(floors, v.type())
        .orElseThrow(() -> new LotFullException(v.type()));
    if (!spot.tryAssign(v))                      // lost the race — retry allocation once
        return park(v);
    Ticket t = Ticket.open(spot.id(), clock.instant());
    tickets.save(t);
    return t;
}

public Receipt unpark(String ticketId) {
    Ticket t = tickets.find(ticketId).orElseThrow(() -> new InvalidTicketException(ticketId));
    t.close();                                   // throws IllegalStateException if already CLOSED
    Money fee = feeStrategy.calculate(t, clock.instant());
    spotById(t.spotId()).release();
    tickets.save(t);
    return new Receipt(t, fee);
}
```

Details graders notice: **`clock` is injected** (`java.time.Clock`) so fee tests don't sleep; `t.close()` owns the exactly-once invariant (State from the behavioral lesson, enum-sized); the race retry is narrated, not hidden.

### Phases 5–6

Extension lands as `WeekendSurgeFee implements FeeStrategy` + one registry entry — zero edits. Demo main: park two vehicles, unpark one, show fee, show `LotFullException` for a truck, show double-unpark rejected. Six tests: fee math (fixed clock), full lot, double unpark, allocation choice, race on last spot (two threads, one wins), remainder-free money.

## The canon — twelve skeletons

| # | Problem | Skeleton | Patterns that carry it | The trap |
|---|---|---|---|---|
| 1 | **Parking lot** | resource allocator | Strategy ×2, State (ticket), guarded Spot | class-tree vehicles; `isFree`+`assign` race |
| 2 | **Splitwise** | money splitter + debt graph | Strategy (splits), Observer (balance updates) | remainder paise; simplify-debts is a graph problem — min cash flow |
| 3 | **BookMyShow** | seat inventory + booking | State (booking), pessimistic hold + TTL, Strategy (pricing) | double-booking race — the SD contention lesson in miniature |
| 4 | **Vending machine** | state machine | State (the canonical one), Factory (products) | scattered transition ifs; change-making greedy fails on odd denominations |
| 5 | **Elevator system** | scheduler | Strategy (scheduling: SCAN/nearest), State (per car), Observer (events) | scheduling all-in-one method; ignore direction = pathological routes |
| 6 | **LRU / in-memory cache** | data structure + policy | Strategy (eviction), Decorator (TTL over base) | O(n) recency; thread-safety hand-waving (concurrency lesson build #2) |
| 7 | **Rate limiter** | token/window per key | Strategy (algorithms), Factory (per-client buckets) | shared bucket across clients; unsynchronized compound refill |
| 8 | **Logger framework** | pipeline + sinks | Chain (levels), Observer/Strategy (appenders), Singleton-as-scope | blocking I/O on caller thread — bounded queue + worker (build #1) |
| 9 | **Snake & Ladder / Chess** | board game engine | Command (moves, undo), State (turns), Factory (pieces) | chess legality all in one method — per-piece movement strategies |
| 10 | **Notification service** | fan-out with fallbacks | Strategy (channels), Chain (fallback order), Decorator (retry/rate-limit) | the structural lesson's decorator-order question, live |
| 11 | **Task scheduler** | delayed execution | Command (jobs), priority queue by time, worker pool | busy-wait polling instead of `DelayQueue`/condition-wait; missed idempotency |
| 12 | **Tic-tac-toe / board validator** | small engine, fast round | minimal — clean model beats patterns here | over-engineering a 30-minute problem is itself the failure |

Read the pattern column and the last two lessons echo: **Strategy appears eleven times.** Machine coding is mostly "find the variation axis, put a strategy seam on it, guard the invariants, demo it running."

## Drill order

Interleave with the [War Room build drills](/citadel/lld/war/build-drills/) (pattern muscle) — this list is problem muscle. Timed, from scratch, `Main` must run:

1. **Parking lot** (90 min) — you've now read the answer; earn it honestly.
2. **Splitwise** (90 min) — money invariants + a real algorithm (min cash flow).
3. **Vending machine** (60 min) — the state machine, both forms from [Drill 3](/citadel/lld/war/build-drills/#drill-3--state-both-ways).
4. **LRU cache** (45 min) — then make it thread-safe out loud.
5. **BookMyShow** (90 min) — bring the SD contention vocabulary (hold + TTL, atomic claim).
6. **Elevator** (90 min) — the hardest scheduling conversation; two strategies minimum.
7. **Logger** (60 min) — async appender with the bounded queue you built in Module 3.
8. **Rate limiter** (45 min) — per-key buckets, `computeIfAbsent` done right.

Rules per drill: phase time boxes from the [protocol](/citadel/lld/lessons/machine-coding-protocol/), no IDE generation beyond getters, `Main` demos happy + two edges, and afterwards write the three-line post-mortem (what slipped, which phase ate time, one thing to steal from the reference solutions online — LLD repos on GitHub and editorials are fine *after* the attempt, never before).
