## Vocabulary — say it right

| Term | In one sentence |
| --- | --- |
| **NER** | Named-entity recognition: find spans in text and label their type. |
| **Entity linking / concept normalisation** | Map a span to a coded concept (UMLS CUI, RxNorm, LOINC, SNOMED, ICD-10). |
| **UMLS / CUI / TUI** | The NLM's unified vocabulary; a Concept Unique Identifier; a semantic Type identifier. |
| **MedCAT / MetaCAT** | Concept linker on spaCy with disambiguation; its meta-annotation models (Status, Subject). |
| **GLiNER** | Zero-shot span NER: labels given at inference time. |
| **Assertion status** | Present / absent / possible / conditional / hypothetical / not the patient (i2b2 2010). |
| **NegEx / ConText** | Cue-and-scope negation algorithm; its generalisation to temporality and experiencer. |
| **Span / offset / provenance** | Verbatim text, its character range (start inclusive, end exclusive), and where it came from (document, page). |
| **Claim check** | Message carries a pointer to the payload stored elsewhere. |
| **At-least-once / idempotent consumer** | Redelivery can happen; every side effect must be safe to repeat. |
| **Dead-letter exchange / queue** | Where rejected messages go instead of looping. |
| **Prefetch (QoS)** | Max unacked messages the broker pushes to one consumer. |
| **Quorum vs classic queue** | Raft-replicated queues with `x-delivery-count`; classic queues lack it. |
| **Transactional outbox** | Write the message to the DB in the same transaction; a relay publishes it. |
| **Structured output / response schema** | The API constrains the model's JSON to a declared schema. |
| **Thinking budget / thought tokens** | Hidden reasoning tokens a model generates before answering; billed, not returned. |
| **Bandwidth-bound decode** | Each generated token streams all weights from GPU memory; tok/s ≈ bandwidth ÷ model bytes. |
| **Q4_K_M** | A 4-bit quantisation format (llama.cpp); 27B params ≈ 18 GB. |
| **BAA** | Business Associate Agreement — the HIPAA contract required before a vendor may touch PHI. |
| **PHI** | Protected Health Information — the 18 identifiers plus any linked clinical data. |
| **RAG** | Retrieve relevant chunks, then generate an answer grounded in them. |
| **Bi-encoder / cross-encoder** | Embed query and doc separately (fast, indexable) / read them jointly (accurate, slow; rerank only). |
| **HNSW** | Graph-based approximate nearest-neighbour index; `m` links per node, `ef` search effort. |
| **Reciprocal rank fusion** | Merge ranked lists by Σ 1/(k+rank); no weights to tune. |
| **pgvector** | Postgres extension for vector columns and ANN indexes. |
| **LOINC / RxNorm** | Lab test codes / normalised drug names. |
| **eGFR, HbA1c, CKD stage 3** | Kidney filtration estimate (&lt; 60 = CKD 3), three-month glucose average (> 6.5 % diabetic range), the stage our demo patient is in. |
| **Triple whammy** | ACE inhibitor + diuretic + NSAID → acute kidney injury risk; the pattern the reasoning pass caught. |
| **STOMP** | Simple text messaging protocol over WebSocket; RabbitMQ relays it. |
| **Flyway** | Versioned SQL migrations; versions must be unique across all merged branches. |

## The eight files to be able to name

| File | What lives there |
| --- | --- |
| `app/workers/consumer.py` | Queue bindings, prefetch, semaphore, the handler, partial-failure logic, webhook fan-out |
| `app/services/ner_service.py` | The three modes, masking, merge/dedupe, span resolution, S3 + DB writes |
| `services/medcat-service/main.py` | MedCAT wrapper, negation rule, header filter, UMLS→ICD/SNOMED lists |
| `app/llm/gemini_api.py` | Prompts, schemas, thinking config, retries, token/cost metrics |
| `app/services/section_service.py` | Meds dedupe, LOINC grouping, unit normalisation, trends, timeline, alerts orchestration |
| `app/services/alert_llm_reasoning.py` + `config/critical_alert_rules.yaml` | The reasoning prompt and the threshold rules |
| `app/services/chunking_service.py` + `app/core/db.py` | 512/50 chunking, MedCPT embeddings, pgvector HNSW DDL |
| `app/clients/section_notifier.py` + `progress_notifier.py` | Webhooks: X-Service-Auth, idempotency key, backoff; per-stage progress events |
