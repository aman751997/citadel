## B. System design interviewer (how does it scale, fail, isolate?)

| Question | 15-second answer | Deeper |
| --- | --- | --- |
| Walk me through one request. | JWT filters → tenant aspect → @PreAuthorize → load definition → policy resolves scope → optional date window in tenant TZ → cache check → validate → compile → execute read-only under bulkhead + 3 s timeout → audit row → overlay column metadata → cache → return. | Page 2, twelve steps |
| How do you protect the OLTP database? | Read-only pool per source DB, SET LOCAL statement_timeout 3 s, LIMIT 5000 after forced sort, bulkhead 10 fail-fast, 60 s result cache. The adapter is a seam, so a replica is a URL change per source (that the move happened is <StatusBadge kind="unverified" label="Replica move" />, confirm it). | Page 6, attack 9 |
| What breaks first at 10× load? | The global bulkhead (429s), then the source DB for large tenants. Next steps: per-tenant bulkheads, materialised views or an OLAP store behind the same adapter interface, async jobs with polling for heavy reports. | Page 3 |
| Why a bulkhead _and_ a pool limit? Aren't they the same? | Pool bounds connections to the DB; bulkhead bounds threads in our JVM and fails fast instead of queueing. A hung spinner is worse than a fast 429 for interactive UI. | Page 3, "Four knobs" |
| How do you handle multi-tenancy? | Two mechanisms. Own DB: Hibernate @Filter armed by a shared aspect. Source DBs: compiler injects tenant_id from the security context (token claim first) unconditionally and refuses unscoped datasources. Branch comes from the branch context, which reads the X-Branch-Id header before the token claim (a gap to volunteer). Cache keys include tenant. Two-tenant IT guards tenant isolation. | Page 6, attacks 4–5 (read the corrected attack 4) |
| Why separate pools per service DB? | Production is one database per service; a Postgres connection cannot span databases. Bonus: a slow billing query cannot starve patient reports. | Page 1 |
| How does the scheduler avoid double-sending on 3 pods? | ShedLock on our own DB: lockAtLeastFor 30 s, lockAtMostFor 9 min, poll every 60 s. Chosen over Redis (optional in our stack) and K8s CronJob (moves logic out of the service). | Page 3 |
| Cache design? | Key = rpt:run:&#123;definitionId&#125;:sha256(tenant, branches, canonical DSL, sorted params). TTL 60 s run / 30 s preview. Prefix eviction on edit (KEYS scan). Only when a Redis bean exists. A cache hit writes no audit row. | Page 6, attack 10 |
| How do dashboards load? | Dashboard row lists tile definition ids; UI fires one /run per tile in parallel. That fan-out is why a bulkhead of 3 produced 429s on a 4-tile dashboard. | Page 4, story 7 |
| Cross-database joins? | Not supported by design. We ask the owning service for a view (billing.v_invoice_revenue_line) so every report stays single-table. Same-DB lookup joins to master tables are supported for display names. | Page 5, step 0; page 2, example 3 |

## C. Security-minded interviewer

| Question | 15-second answer | Deeper |
| --- | --- | --- |
| How is this not a SQL injection machine? | Values are bound, identifiers are looked up in the catalog, structure uses ordinals, operators and aggregations are enums, aliases are sanitised and quoted. Exactly one class builds SQL text and it is tested. | Page 6, attacks 1–3 |
| Why can't you bind a column name? | SQL prepared statements bind values, not identifiers; the planner needs identifiers at prepare time. So the only safe identifier is one the server already knows: hence the catalog. | Page 6, attack 2 |
| How do you prevent PII leakage? | Allow-list catalog (raw identifiers are not listed) plus a regex block on \*\_vault_id / \*\_token / \*\_hash applied to field key and physical column. Plus k-anonymity via HAVING for small groups, for whatever k the report carries (no server floor; the excludePatientIdentifiers flag is not read). | Page 6, attacks 6–7 |
| What about platform staff? | PLATFORM\_\* roles get 403 from the access policy before anything runs. They have no tenant claim, so this policy layer is load-bearing. | Page 6, defence in depth |
| Audit? | Synchronous INSERT per executed run with user, SQL hash, datasource, row count, truncated flag, elapsed ms, tenant (the definition id column exists but is not filled; cache hits are not audited). Async would lose tenant context and could drop rows on crash. | Page 6, audit |
| Read-only guarantee? | Hikari readOnly, enforceReadOnly on the tx manager, TransactionTemplate readOnly. A compiler bug that emitted UPDATE would be refused by the read-only transaction. A SELECT-only DB role would be a further layer. <StatusBadge kind="unverified" /> I could not see the grants; confirm before claiming it. | Page 6 |

## D. Hands-on / coding interviewer

| Question | 15-second answer | Deeper |
| --- | --- | --- |
| Show me the SQL for "appointments by status" for a branch admin. | SELECT status::text AS "Status", COUNT(\*) AS "Appointments" FROM patient.appointments WHERE tenant_id = :tenant_id AND branch_id::text IN (:branch_ids) AND status::text IN (:flt_0) GROUP BY 1 HAVING COUNT(\*) >= :min_group_size ORDER BY 2 DESC LIMIT :row_limit | Page 2, example 1 |
| Why the ::text casts? | Postgres has no enum = varchar operator, and no uuid = varchar either. Bound params arrive as varchar, so enum and uuid columns are cast to text. Date filters cast the _parameter_ instead (::timestamptz) so the index on the column stays usable. | Page 2, clause notes |
| How do time buckets work? | date_trunc('month', col AT TIME ZONE :tz). HOUR_OF_DAY uses EXTRACT(HOUR FROM col AT TIME ZONE :tz) for a 0–23 distribution. TZ is a bound param from admin-service, cached 10 min, fallback Asia/Kolkata. | Page 2, example 2 |
| Why ordinals in GROUP BY / ORDER BY? | So no user string shapes the statement. Aliases only appear in SELECT, sanitised. "Appointments" resolves to position 2 at compile time. | Page 2 |
| How do lookup joins work without breaking existing SQL? | A field with lookup_table / lookup_key / lookup_display_column registers LEFT JOIN lead.lead_sources lk0 ON lk0.id = f.source_id once per FK, projects lk0.name, and the fact table gets alias f only when a lookup exists. Computed columns use a &#123;f&#125;. placeholder. Non-lookup SQL is meant to stay unchanged; a test covers the placeholder case, but I found no test for every non-lookup query. | Page 2, example 3; page 4, story 4 |
| How is the date range picker implemented? | ExportDateRangeResolver turns TODAY / YESTERDAY / THIS_WEEK / THIS_MONTH / CUSTOM into a BETWEEN on the datasource's default_date_column in the tenant zone; upper bound = start of next period minus 1 µs so boundaries never double count. | Page 2, step 7 |
| How is the catalog loaded? | Immutable snapshot in an AtomicReference, rebuilt every 5 min by CatalogLoader (and on POST /catalog/refresh). Readers never lock; a half-loaded catalog is impossible. | Page 1 |
| What does the engine flag do? | reporting.engine.stub selects CompilingReportEngineService or StubReportEngineService behind one interface. Ships dark, flips per environment, UI develops against canned data. | Page 1 |
| What do the tests cover? | 33 Java files under src/test (a few are base or config helpers): QueryCompilerTest (invariants), CatalogValidatorTest, ReportAccessPolicyTest, PostgresJdbcAdapter unit + IT, TenantIsolationIT (two tenants; get, list and system-template reads), six real-engine *E2EIT classes by business domain (appointments, billing, pharmacy stock type, telecaller, refunds, patient refund requests), controller slices. There is no test that sends a spoofed X-Branch-Id. | Brief §5 |
| Honest gaps? | Save validates but does not compile (a definition can validate yet fail at run). Audit dsl_hash hashes the SQL not the DSL, and definition id is not recorded. Global bulkhead. KEYS scan eviction. Stale Javadoc on CompiledReport. Branch header precedence. k and excludePatientIdentifiers handling. | Pages 4 and 6 |

## Interactive mock interview

Answer out loud, then open the box. Three levels: Basic (explain it), Intermediate (defend it), Advanced (break it).

### Basic

<Reveal q="Draw the architecture and name the components.">

UI with a JWT calls `reporting-service`. Inside: access policy, catalog validator, query compiler, Postgres JDBC adapter (read-only, 3 s timeout, bulkhead 10, 5000-row cap), audit row. It writes definitions, dashboards, schedules and audit to its own `reporting_db`, and reads from one read-only pool per service database. Optional pieces: Redis result cache, admin-service for tenant timezone, notification-service for scheduled CSV email.

</Reveal>

<Reveal q="What is in a report definition?">

An eight-field JSON DSL: datasource, chartType, dimensions, measures, filters, sort, limit, privacy. It references catalog fields by key, never raw columns.

</Reveal>

<Reveal q="What does a scheduled report do, and who is it run as?">

A poller runs every 60 s under a ShedLock (lockAtLeastFor 30 s, lockAtMostFor 9 min), finds due schedules, runs the definition with the creator's stored branch scope, saves a CSV artifact, then emails it through notification-service. Delivery failure marks the artifact failed but the file is kept. Next run time always advances, even on failure.

</Reveal>

### Intermediate

<Reveal q="Why seed the catalog with Flyway and not an admin UI?">

Catalog rows widen what can be queried and their physical names go into SQL text, so changes are security changes and go through PR review, versioning and rollback.

</Reveal>

<Reveal q="Why is the row cap applied after a forced sort?">

Without a deterministic order the cap would return arbitrary rows and the chart would lie. With no user sort on a grouped query the compiler orders by the first measure descending so the biggest groups survive. A result with 5000 rows sets the truncated flag.

</Reveal>

<Reveal q="Why a bulkhead and a pool limit? Are they the same thing?">

No. The pool bounds connections to the database. The bulkhead bounds concurrent executions in our JVM and fails fast with a 429 instead of queueing, which suits an interactive UI.

</Reveal>

### Advanced

<Reveal q="A branch admin reports seeing another branch's data. Where do you look?">

First the branch context: the `X-Branch-Id` header is read before the token claim, and nothing compares the header with the branches in the token (unless a gateway handles it, which I have not verified). Then the access policy output for that user, the emitted SQL (branch predicate present?), and the cache key (it includes branches). Fix direction: intersect header and token branches in the policy and add a spoofed-header test. <StatusBadge kind="hypothetical" />

</Reveal>

<Reveal q="Product wants every report to hide groups smaller than 5. Is that already guaranteed?">

No. The compiler uses the report's own `minimumGroupSize` and omits the HAVING when it is 0 or missing; some seeded revenue reports deliberately use 1. To guarantee it you need a server-side minimum, for example per datasource in the catalog, applied as the larger of the two. <StatusBadge kind="hypothetical" />

</Reveal>

<Reveal q="How would you let a power user write ad-hoc queries safely?">

Not through this DSL. Options: an embedded BI tool with row-level security on a read replica, or a constrained query builder that still compiles against the catalog. Either needs a decision on how tenant and branch rules are enforced inside it. Discussion only. <StatusBadge kind="hypothetical" />

</Reveal>

<Fragment slot="short">

On 2026-09-01 dashboards with four or more tiles returned 429. The bulkhead was 3 with zero wait and the UI fires one run per tile in parallel. We raised it to 10 by config, kept the protection, and wrote down per-tenant bulkheads and staggered tile loads as follow-ups.

</Fragment>
<Fragment slot="medium">

Situation: real users hit HTTP 429 loading dashboards. Task: explain it and fix it without removing the protection. Action: traced it to the bulkhead doing what it was designed to do, sized for single reports, not dashboard fan-out; changed `maxConcurrentCalls` from 3 to 10 in the default and production profiles (PR #1706). Result: dashboards load; not quantified in source. Lesson: size limits from the caller's fan-out, and a fail-fast limit that fires is a limit that works.

</Fragment>

## Vocabulary (one line each)

| Term | Meaning here |
| --- | --- |
| Metadata-driven | Behaviour comes from rows in tables (catalog, definitions), not from code paths per report. |
| DSL | Domain-specific language: our eight-field JSON describing a report. |
| Catalog / semantic layer | Allow-list of datasources and fields with roles, types, allowed aggregations and operators. The type system. |
| Dimension / measure | What you group by / what you aggregate. Borrowed from OLAP and Cube.dev. |
| Time bucket | HOUR, HOUR_OF_DAY, DAY, WEEK, MONTH, QUARTER, YEAR granularity for a time dimension. |
| Access scope | (tenantId, ALL \| RESTRICTED \| DENY, branchIds) derived from roles plus the tenant and branch context by ReportAccessPolicy. |
| k-anonymity | Suppress any group with fewer than k members; here HAVING COUNT(\*) >= k. |
| Bulkhead | Concurrency limiter; ship-hull metaphor. resilience4j, fail-fast at 10. |
| SET LOCAL | Postgres setting scoped to the current transaction; our statement_timeout lives there. |
| ShedLock | DB-backed distributed lock so one pod runs a scheduled job. |
| System template | report_definition with owner=PLATFORM, is_system=true: runnable by any tenant, editable by none, clonable. |
| Lookup join | Same-DB LEFT JOIN to a master table for a display name, declared in catalog_field. |
| Claim-check / seam / snapshot | Design patterns you will name: adapter seam (swap DB target), immutable snapshot (AtomicReference catalog). |

## Further reading (curated, in order of usefulness)

* [OWASP SQL Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html) — prepared statements, allow-list input validation for identifiers. Our design is defences 1 and 3.
* [OWASP Query Parameterization](https://cheatsheetseries.owasp.org/cheatsheets/Query_Parameterization_Cheat_Sheet.html) — why identifiers cannot be parameters, with Java examples.
* [PostgreSQL statement_timeout](https://www.postgresql.org/docs/current/runtime-config-client.html#GUC-STATEMENT-TIMEOUT) and [SET LOCAL](https://www.postgresql.org/docs/current/sql-set.html).
* [PostgreSQL AT TIME ZONE](https://www.postgresql.org/docs/current/functions-datetime.html#FUNCTIONS-DATETIME-ZONECONVERT) and [date_trunc](https://www.postgresql.org/docs/current/functions-datetime.html#FUNCTIONS-DATETIME-TRUNC) — the timezone bucketing trick.
* [resilience4j Bulkhead](https://resilience4j.readme.io/docs/bulkhead) — semaphore vs thread-pool bulkhead; we use semaphore with zero wait.
* [ShedLock](https://github.com/lukas-krecan/ShedLock) — lockAtMostFor / lockAtLeastFor semantics.
* [HikariCP](https://github.com/brettwooldridge/HikariCP) — readOnly, pool sizing ([About Pool Sizing](https://github.com/brettwooldridge/HikariCP/wiki/About-Pool-Sizing)).
* [Hibernate @Filter](https://docs.jboss.org/hibernate/orm/6.4/userguide/html_single/Hibernate_User_Guide.html#pc-filter) — session-scoped, must be enabled per session (war story 2).
* [k-anonymity](https://en.wikipedia.org/wiki/K-anonymity) and [l-diversity](https://en.wikipedia.org/wiki/L-diversity) — know the limits of what we claim.
* [Cube.dev semantic layer](https://cube.dev/docs/product/data-modeling/concepts) and [Apache Superset row-level security](https://superset.apache.org/docs/security/) — the "build vs embed" comparison points.
* [Grafana provisioning](https://grafana.com/docs/grafana/latest/administration/provisioning/) and [Prometheus data model](https://prometheus.io/docs/concepts/data_model/) — the analogy's source material.
* [Fowler: Query Object pattern](https://martinfowler.com/eaaCatalog/queryObject.html) and [Fowler on DSLs](https://martinfowler.com/bliki/DomainSpecificLanguage.html).
* [Redis KEYS](https://redis.io/docs/latest/commands/keys/) vs [SCAN](https://redis.io/docs/latest/commands/scan/) — the eviction gap.
* [Flyway documentation](https://documentation.red-gate.com/fd) — versioned migrations as the deployment unit for data.
* [India DPDP Act 2023](https://www.meity.gov.in/data-protection-framework) — the audit-trail conversation.
