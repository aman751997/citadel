## Design decisions and trade-offs

<StatusBadge kind="tested" label="Decisions made in the prototype" /> The first four columns describe what was built in the proof of concept. The "Revisit when" column is reasoning about scale, not measured. <StatusBadge kind="hypothetical" label="Revisit when = hypothetical" />

| Decision | Explain it to a friend | Alternatives | Why this | Revisit when |
| --- | --- | --- | --- | --- |
| **LiveKit (self-hosted) as the SFU** | "An open-source video server we run ourselves; it forwards packets, records tracks, and emits webhooks." | Twilio Video / Daily / Agora (managed); raw WebRTC mesh | Data residency (PHI stays on our infra), per-track egress out of the box, server SDK for tokens and room control, no per-minute billing for a POC. | If ops cost of running the SFU outweighs managed pricing at production scale; LiveKit Cloud is a drop-in. |
| **Track egress per mic, no diarization** | "Record each person separately so we never have to guess who said what." | Room composite + pyannote / WhisperX | Exact labels; no GPU diarization pass; Opus pass-through. Moves difficulty to alignment and half-silent tracks, both solved deterministically. | Three or more participants with cross-talk; then per-track still works, alignment just has more tracks. |
| **Whisper on-device (MLX)** | "Transcribe on the Mac's own GPU so audio never leaves the machine during the demo." | Cloud STT (Deepgram, Sarvam, Google); faster-whisper on a CUDA box | Zero data egress for audio, no API cost, under a minute for demo-length calls. The provider seam is one function. | Production: managed Indic STT (Sarvam) or a GPU worker pool; laptops are not servers. |
| **Consent as a set that must empty** | "Recording starts only when the last person says yes." | Boolean flag; implied consent by joining | Late joiners are not covered; decline aborts; revoke is distinct from stop. Matches DPDP purpose-and-consent principles and the Telemedicine Practice Guidelines. | Never loosen. Tighten by persisting consent events with timestamps. |
| **Dual-path control messages** | "Send every control message two ways and de-duplicate, because one way fails for silent participants." | Data channel only; HTTP only | Mic-less participants have no publisher connection; data-channel sends time out. HTTP relay via `sendData` reaches the subscriber side. Receivers are idempotent. | If we move to a proper backend, control messages go through the server only. |
| **Redis on the host, not in Docker** | "Docker's port forwarding added enough lag that the video server kept thinking its recorder had died." | Redis in compose | Docker Desktop's host→container port proxy was flaky; LiveKit routing depends on low-latency Redis keepalives. Egress reaches Redis via `host.docker.internal`. | On Linux hosts (no Docker Desktop proxy) it can go back into compose. |
| **Filesystem as the database** | "Each recording session is a folder; the files are the state." | Postgres + S3 | POC speed; easy to demo the compliance close by showing an empty folder. The layout is already the shape of an object-store prefix. | Production, immediately: metadata in Postgres, blobs in object storage with lifecycle rules. |
| **Serialised transcription** | "One Whisper job at a time so two calls do not fight for the GPU." | Parallel jobs; external queue | Single GPU; a promise chain is a queue with zero infrastructure. Failed jobs keep their audio for retry. | Production: a real queue (RabbitMQ, as in the AI pipeline) and a worker pool. |
| **Synchronous delete after success** | "The moment the transcript is written, the audio is gone." | Retention by default | Data minimisation; `KEEP_AUDIO=1` models the 30-day hospital opt-in. Failure path retains for retry. | Per-tenant retention policy in production, with the same default. |
| **Write-once signed note** | "You can sign once. The original machine transcript is never touched." | Editable note; overwrite transcript | Medico-legal: immutable source, attributable human edits, 409 on re-sign. | Add amendment records (new versions with reasons) rather than allowing edits. |

## War stories (STAR)

Each story is a real problem from building the proof of concept. The source gives qualitative outcomes only, so each Result is marked "not quantified in source".

### 1. The consent modal never appeared on the patient's phone

**Situation.** Patient joined audio-only with camera off, sometimes with mic off too. Doctor pressed REC; nothing happened on the phone. **Task.** Find why a reliable data-channel message vanished. **Action.** Traced to WebRTC topology: a participant who publishes nothing has no publisher peer connection, and data-channel sends from that side time out. Rather than force everyone to publish, added an HTTP relay through the server's `sendData` and sent every control message both ways, with receiver-side de-duplication so only the first copy of the final accept starts recording. **Result (not quantified in source).** Consent works for silent participants; double delivery is harmless. **Lesson.** Know the transport's topology before trusting "reliable".

### 2. Whisper said "Thank you." to an empty room

**Situation.** Per-speaker tracks are half silence. Transcripts contained "Thank you.", "Thanks for watching.", and a Russian "to be continued". **Task.** Remove hallucinations without dropping real speech. **Action.** Disabled `condition_on_previous_text` so one hallucination could not seed the next; stacked Whisper's own three quality signals plus a minimum duration; then added the decisive gate: measure the segment window's peak with `ffmpeg volumedetect` and drop anything below −35 dBFS. **Result (not quantified in source).** Outro phrases gone from silent windows; real speech untouched. Some short repeated phrases still leak, which I say up front. **Lesson.** When a model's confidence is unreliable, check the physical signal.

### 3. Speakers appeared in the wrong order

**Situation.** Two files, each starting at 0:00. Interleaving by file time put the patient's answer before the doctor's question. **Task.** Put both on one clock. **Action.** Harvested `startedAt` (ns) from each egress result, added it as a per-track offset, sorted, rebased to the first utterance. Found the result record is written asynchronously, so finalise polls `listEgress` until COMPLETE (≤10 s) before writing the manifest. Added a relative-time fallback when any timestamp is missing. **Result (not quantified in source).** Measured skew of 29–74 ms is corrected; order is right. **Lesson.** Independent recorders need a shared reference, and the reference arrives late.

### 4. LiveKit kept losing its recorder (Redis latency)

**Situation.** Egress StartEgress calls timed out; LiveKit logged stale keepalives. **Task.** Stabilise coordination between the server binary and the Docker egress. **Action.** Root cause was Docker Desktop's host→container port proxy adding latency and stalling. Moved Redis to the host via Homebrew; egress connects through `host.docker.internal`. Also replaced LiveKit `--dev` mode with a config file, since egress needs shared Redis. **Result (not quantified in source).** Recording start became reliable. **Lesson.** Latency-sensitive coordination should not cross a virtualised network boundary on a laptop.

### 5. Docker wedged before every demo

**Situation.** Docker Desktop hung intermittently (CLI hangs, port proxy stalls), making egress calls time out. **Task.** Make the start script self-healing so a demo never depends on a manual restart. **Action.** Probe the daemon with `curl --unix-socket … /_ping --max-time 4`; on failure, quit Docker Desktop via AppleScript, kill the backend, reopen, retry up to 40 × 5 s; then run health checks (Redis PONG, 200s on 7880/3001/5173, compose status). **Result (not quantified in source).** "Everything must say 200 / PONG / Up" became a one-command pre-demo gate. **Lesson.** Automate the flaky dependency's recovery, and make the health check explicit.

### 6. The patient's screen kept showing a dead call

**Situation.** Doctor pressed End and just left; the patient saw one frozen tile. **Task.** Make End mean end. **Action.** End now finalises the recording first, then `deleteRoom`; clients receive `ROOM_DELETED` and render "Consultation ended"; the doctor is routed to the notes screen. **Result (not quantified in source).** Clean close for both parties, and the egress stops before the room disappears. **Lesson.** Order of operations at shutdown matters: stop recorders, then tear down the room.

### 7. A browser crash mid-call would have lost the recording

**Situation.** Finalise only ran when a button was pressed. **Task.** Cover the "tab closed" path. **Action.** Registered the `room_finished` webhook, verified with the raw body and the LiveKit signature, calling the same idempotent finalise that removes the room from the active map before any await and ignores already-ended egresses. **Result (not quantified in source).** Three entry points, one outcome. **Lesson.** Every background path needs the same idempotent handler as the happy path.

## What I would change for production (say this unprompted)

<StatusBadge kind="planned" label="Every row is planned, none is built" />

| Gap today | Production change |
| --- | --- |
| `/token` is unauthenticated; role is a client-chosen string; API key/secret are `devkey`/`secret` | Authenticate users (our auth-service JWT), derive role server-side, mint LiveKit tokens with short TTL and scoped grants (`roomRecord` only for the service), rotate secrets |
| Privileged routes (start/stop/end/sign/relay) open to anyone | Authorisation per route; only the consulting doctor may record, end, or sign |
| Self-signed TLS; plaintext internal hops; Redis unauthenticated; no E2EE | CA-signed TLS, TLS or private network for internal hops, Redis auth; evaluate LiveKit E2EE for media |
| Filesystem state; `activeRecordings` in memory (lost on restart) | Postgres for sessions and consent events; object storage with lifecycle rules for artefacts |
| Whisper on a laptop; serialised in-process queue | Managed Indic STT (Sarvam) or GPU workers behind RabbitMQ; the `transcribe_file()` seam is already there |
| Hallucination gates leak short repeated phrases | Silero VAD in front of Whisper; cross-segment repetition filter; per-tenant language lock |
| Egress poll gives up at 10 s → silent relative alignment | Poll longer or subscribe to `egress_ended` webhook; fail loudly if timestamps are missing |
| Transcripts and summaries retained forever | Retention policy per tenant; purge job; audit of access |
| No tests | Unit tests for gates and alignment (pure functions), contract tests for the API, a Playwright E2E for consent |
| `livekit/egress:latest`; duplicated `parseIdentity` in client and server | Pin versions; share a types package |

### Think first: three levels

Answer out loud before opening each one.

**Basic: explain the architecture**

<Reveal q="Describe the system in 30 seconds without looking at the diagram.">

A React app talks through one HTTPS Vite origin to an Express token server and a LiveKit SFU. The doctor requests recording, consent is collected, and one track egress per microphone writes Opus files. On end, the server writes a manifest, runs Whisper locally, aligns and filters the transcript, asks MedGemma for a five-section draft, and the doctor signs a write-once note. It runs on one Mac plus a phone and is a proof of concept.

</Reveal>

<Reveal q="Which hop carries media and why does it bypass the proxy?">

WebRTC media goes directly between the browser and livekit-server over UDP 50000-50200, encrypted with DTLS-SRTP. The proxy only carries the app, the API and the signalling websocket.

</Reveal>

**Intermediate: defend decisions**

<Reveal q="Why not diarization? What did that choice cost you?">

Exact speaker labels by construction and no GPU diarization pass. The cost is aligning independent files, solved with egress start timestamps, and half-silent tracks causing hallucinations, solved with the five gates.

</Reveal>

<Reveal q="Why is finalise safe to call from three places?">

It removes the room from the in-memory map before any await, so a second caller finds nothing, and it ignores egresses that already ended.

</Reveal>

**Advanced: failures, scaling, alternatives**

<Reveal q="What happens if the egress never reaches COMPLETE within 10 seconds?">

startedAtNs is missing (0), so transcribe.py logs a warning and all tracks fall back to relative time. Order can be off by the egress start gap, which was 29-74 ms in the measured sessions. The fix is to poll longer or use the egress_ended webhook and fail loudly. <StatusBadge kind="hypothetical" label="Improvement" />

</Reveal>

<Reveal q="Your gates still let some phrases through. What is the next layer?">

A real VAD such as Silero in front of Whisper, a repetition filter across segments, and a per-tenant language lock. None is built. <StatusBadge kind="planned" />

</Reveal>

<Reveal q="Move this to production for many hospitals. What breaks first?">

The unauthenticated API and client-chosen roles, the in-memory state and filesystem storage, and laptop-bound transcription. The gap table above lists the fixes: server-derived roles, Postgres and object storage, GPU workers or managed Indic STT behind a queue. No scale numbers exist for this proof of concept. <StatusBadge kind="unverified" label="No load testing" />

</Reveal>
